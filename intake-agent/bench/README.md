# bench — the end-to-end harness

Nothing here is part of the extension. It drives the built `dist/` in a real
Chromium and grades the result against the input file, standing in for the human
reviewer.

| File | What it is |
|---|---|
| `lane.mjs` | one lane = one browser, one profile, one platform tab, one panel — plus the grader that diffs the built study against the input file |
| `all.mjs` | the matrix: `PLATFORMS × INPUTS`. `node bench/all.mjs [lane…]`, where a bare platform or input name means every lane on it. Importable for `LANES` alone |
| `matrix.sh` | runs the matrix in batches, so sixteen browsers never contend for one machine. `bench/matrix.sh <batch> <reps>` |
| `summarize.mjs` | one table over a directory of lane results (default `out/matrix`) |
| `gate.mjs` | the human gate end to end: run a lane, answer the cards a person can answer, Resume, report what that unblocked |
| `probe.mjs` | diagnostic — dumps what the agent's perception layer sees on a page, driving it by visible name |

`out/` is gitignored: the lane results are large JSON dumps of the built study,
regenerated by a run.

The grader is the only thing that touches the mock's `__readState()` oracle. The
agent never does, and must not.
